# 揮手鑑古｜尋寶清明上河圖

用手掌揮開迷霧，走入古畫尋寶。適合小朋友與家長一齊玩嘅廣東話網頁遊戲，亦展示 AI 點樣將鏡頭入面嘅手部關鍵點變成操作指令。

**[立即遊玩](https://wcy.hk/QingMing-Hand-Treasure/)** · 建議用電腦版 Chrome／Edge 配合鏡頭揮手；滑鼠只作輔助操作。

## 大屏幕現場診斷與流暢模式

正式遊戲右上角可按「效能數據」，即時展開右欄的大字數據；再按「收起數據」或面板的 × 返回 AI 教學視窗。開關不會重開鏡頭或清除進度。面板只會在按下按鈕後開啟；舊網址即使帶有 `diagnostics=1` 亦不會自動顯示。工作人員可量度取像、AI、總往返毫秒及實際辨識／畫面更新率。數據只在本機顯示，不傳送影像或診斷資料。

介紹頁上方保留全螢幕、畫卷簡介、效能數據及重新開始，可用滑鼠或手勢停留操作；毋須先進入尋寶。工具列保留在介紹卡片上方，較窄視窗仍顯示畫卷簡介；卡片按實際工具列高度自動縮放，保持一頁顯示。效能數據按鈕沿用簡介／重新開始的普通工具樣式。介紹卡片已移除重複的印章與遊戲標題，放大畫卷介紹及玩法文字。

- 雙人標準：原有雙手模式。
- 雙人流暢：保留兩人，鏡頭優先 320 × 240／12 fps，模型輸入寬 256、最多每秒辨識 6 次，遊戲繪圖 20 fps。
- 單人省電：必須由工作人員明確選取，只辨識一隻手；介紹頁會顯示單人模式。
- 自動引擎優先 GPU，只在載入失敗或 GPU 執行錯誤時回退 CPU。取消以「GPU 超過 120 ms」自動改用 CPU：Android 大屏幕實測 GPU 約 220 ms，而 CPU 約 533 ms，慢 GPU 不代表 CPU 更快。工作人員仍可手動比較兩者。
- 辨識模型新增 Auto／Lite／Full，與單雙人模式、CPU／GPU 各自獨立。Auto 未有本機記錄時先在 Android 使用 Lite、其他電腦使用 Full，再按實測調節；Lite 同時減輕手掌偵測與 21 點定位兩個神經網絡，保留雙手。小手、遮擋及遠距離的辨識穩定性可能較低，可切回 Full。
- 大屏幕比較連結：`?performance=balanced&engine=auto&model=lite`。診斷行會顯示「AI Lite」或「AI Full」。保持同一模式、距離、手數量比較；桌面測試不能保證實機流暢程度。按「套用並重新開始」會記住運算模式，並在當前網址套用引擎與模型；一般入口預設自動。

鏡頭會先嘗試限制實際解析度；硬件不支援時退回 ideal 設定，並顯示實際鏡頭尺寸。送入 Worker 前先在小畫布縮小影像，避免把 4K 原始影格交給辨識取像流程。同時最多一張影像處理中，不會累積影格。此版仍需要現場數據來判斷個別大屏幕的瓶頸，不能以桌面測試代替實機確認。

### 自動辨識模型

每次從一般遊戲入口開啟，模型和辨識引擎都預設 Auto；舊版儲存的 Lite／Full／CPU 不再鎖定裝置，毋須工作人員逐部機設定。運算模式（單雙人／流暢）仍保留。自動模型先沿用本機最近七日、相同引擎／手數／運算模式的已量度選擇；沒有記錄時，Android 先用 Lite，其他電腦先用 Full。模型切換只重建 Worker 內的辨識器，保留鏡頭、雙人數量、關卡及已找到的寶物。切換期間暫停舊光圈，完成後恢復；畫面和滑鼠仍可操作。

- 先略過五幀暖機，再收集八個「有手」畫格的運算時間中位數，不把沒有手或一兩次停頓當成裝置效能。
- Full 持續超過 100 ms 時切 Lite；其後本次鏡頭工作階段不再升回 Full，防止反覆切換。
- Lite 首輪中位數低於 35 ms 才試 Full；Full 超出預算會回 Lite，未超出則繼續監測，裝置稍後變慢亦可降級。
- 模型資產載入失敗或切換載入超過 15 秒，會嘗試還原上一個模型，停止本輪自動嘗試。GPU／CPU 的選擇不因模型調節而盲目改變。
- 工作人員仍可在設定手動比較 Lite／Full 或 CPU；明確的網址參數只影響該網址。手動選擇不再儲存為一般入口的預設。重新由一般遊戲網址開啟，就會恢復自動調節。

100／35 ms 是本遊戲的調節門檻，並非對所有硬件的效能保證。實際辨識能力仍受手掌大小、距離、遮擋及瀏覽器影響。

## Android 大屏幕效能

手勢模型在 Web Worker 內優先使用 GPU；硬件不支援或 GPU context 中斷時自動改回 CPU，保留最多兩手辨識。Android 預設最多每秒辨識 10 次，辨識輸入寬度為 416 像素；辨識持續繁忙時自動改為 320 像素並在辨識之間留出休息時間，讓畫面和觸控有運算資源。這不改變右欄實景與骨架的位置。

遊戲繪圖最多每秒 30 幀，鏡頭預覽另以約每秒 12 幀（Android）／15 幀（電腦）更新。每個光圈只合成 314 × 314 像素附近區域，重用柔邊遮罩，取代逐手複製整張 1280 × 720 古畫；光圈遮罩面積減少約 89%。座標軌跡格的內部解析度亦設上限。雙人停留、線索粒子及圓形進度盤仍保留。

程式入口和改動過的依賴附版本編號，避免舊瀏覽器快取混用新版程式。Android 螢幕仍需在實際設備驗證 GPU 驅動、鏡頭和瀏覽器相容性。`cameraPanel` 的 `data-diagnostics` 提供 delegate、辨識耗時及輸入寬度，方便不錄影地排查效能。

## 全螢幕展示

公開網頁首次用滑鼠點擊畫面會嘗試進入全螢幕；瀏覽器要求實際點擊授權，純鏡頭手勢不能觸發。右上角「獲得線索」旁新增「全螢幕」按鈕，可隨時用滑鼠切換；手勢停留可退出已開啟的網頁全螢幕；未開啟時會提示滑鼠點擊或按 F11。按 Esc 亦可退出。退出後不會因其他操作強行再進入。瀏覽器不支援網頁全螢幕時可用 F11。

本機以 `Start Game.cmd` 啟動時，會以 `--start-fullscreen` 開啟 Edge／Chrome 新視窗，適合展覽，可按 F11 退出瀏覽器全螢幕。若系統改用其他預設瀏覽器，仍可按網頁的「全螢幕」按鈕。

## 合作尋寶與線索光點

一人或兩人都可直接玩，不用切換模式。兩位玩家並排站好，每人舉起一隻張開的手，鏡頭最多同時辨識兩隻手；P1 金色、P2 青綠色光圈各有獨立的停留計時，共享五關十件進度。右欄保留綠色骨架、玩家編號及兩條細軌跡。模型辨識手掌，並不識別人物；一人舉雙手也會控制兩個光圈。盡量保持手掌分開，避免交疊遮擋。

右上角「獲得線索」支援滑鼠及任一玩家手勢停留。金色光點約 1.25 秒飛向一件未找到的物件，必要時先平移畫卷，目標短暫亮起至約 12 秒；仍須自行照住目標約兩秒才算找到。再按可提示另一件未找到的物件，不會自動得分。同時找到兩件時，兩個成果都會保留，逐張顯示介紹和廣東話講解，讀完才進入下一關。

## 點樣玩

1. 開啟頁面並允許鏡頭後，介紹頁已可顯示實景與手勢。張開手掌，將光點移到「揮手入畫」，停留即可開始；亦可用滑鼠輔助。
2. 張開手掌移動光圈；家長可隨時用滑鼠輔助，滑鼠停低約三秒後，手勢可以接返。
3. 照住物件約兩秒，聽廣東話講解用途與畫中生活。每關由六件候選物件隨機抽兩件，五關仍共十件。
4. 通關後，金色光粒子用約 3 秒消融灰幕，再用約 48 秒由城內到城外慢慢回望全彩長卷；抵達城門即顯示完成畫面，背景分頁不會跳過回放。
5. 張開手掌停留或按「再玩一次」，返回玩法說明，鏡頭保持啟動，下一位玩家可直接揮手開始。

介紹頁以單屏排版顯示畫卷簡介、三步玩法及開始按鈕，背景有半透明長卷緩緩移動，不用上下捲動。活動海報只放本專案 README，遊戲內不顯示。較矮視窗會自動調整整張介紹卡的比例。「畫卷簡介」可重新打開介紹；廣東話講解長期開啟，配樂預設播放，右欄不設聲音開關。操作員按 C 可開啟鏡頭設定，按 R 返回玩法說明。

每次新一局會重新抽題，並避開上一局各關搵過的兩件物件。候選物件由十件增加至三十件，新增小狗、陶罐、貨車、老樹、涼亭等細節。同一瀏覽器只在本機儲存上一局的物件編號；禁止儲存時，當次開啟期間仍可避開上一局。

## 畫卷與 AI

遊戲使用1736年由五位清宮畫家合作完成、國立故宮博物院收藏嘅「清院本《清明上河圖》」，與北宋張擇端本屬不同版本。主頁附[故宮作品資料](https://digitalarchive.npm.gov.tw/Collection/Detail/3782?dep=P)。路線由城門外、城內大街、街市、河岸園林到深處樓閣，係遊戲策展路線。

MediaPipe Hand Landmarker 找出手部21個關鍵點，程式再計算手掌位置、手指伸展程度及平滑軌跡。右欄直接顯示實景與骨架，放大的座標軌跡格會隨可用空間伸展，方便理解 AI 與程式各自做緊乜。**鏡頭影像只在玩家瀏覽器處理，不錄影、不上傳，不需要帳戶。** 首次使用會下載本專案內嘅模型與素材。

廣東話講解為預先生成嘅本機 MP3；背景五聲音階配樂與尋寶音效由 Web Audio 即時合成，講解時音樂會自動降低。瀏覽器若限制自動發聲，需先輕按畫面或鍵盤一次。公開版使用原畫放大細節與自製光效，沒有轉載故宮動畫影片。

畫卷以最大 2048 像素寬的小圖分塊載入，先顯示輕量預覽，再補清晰細節。全彩回望不會逐幀重新計算灰階；通關消融使用低解像遮罩及預先繪製的光點，減少舊電腦的繪圖負擔。

## 本機開發

需要 Python 3；修改與測試程式另需 Node.js 22。

```sh
python start_game.py
node --test tests/*.test.mjs
python scripts/build_site.py
```

不要直接以 file:// 開啟；鏡頭需要 HTTPS 或 localhost。手機可瀏覽介紹，遊戲介面以電腦橫向畫面為主。

- `chapters.js`：五關各六件候選物件、座標及廣東話描述。
- `round-selection.mjs`：每關隨機抽兩件，避開上一局題目。
- `portal.js`：光圈、尋寶、轉場與通關演出。
- `scroll-atlas.mjs`／`reveal.mjs`：分塊畫卷、預覽後備與輕量通關消融。
- `input-router.mjs`：滑鼠優先接手與手勢恢復規則。
- `camera.mjs`／`hand-worker.mjs`：鏡頭、關鍵點、背景 AI 推論。
- `game-audio.mjs`：配樂、提示音與廣東話播放。
- `site-files.json`：實際網站檔案與 SHA-256。更新程式或素材時，亦需同步更新相應雜湊值。

右欄下方以三步大字說明「手部關鍵點辨識 → 座標映射與平滑處理 → 停留判定與事件觸發」，每步附簡短說明，方便工作人員講解。已移除右欄底部的本機處理提示文字；影像處理方式不受版面文字調整影響。

啟動區以較大的「舉手提示 → 停留說明 → 開始按鈕」排列，移除介紹卡最底的鏡頭提示。尋寶時只保留少量閃光星點，不畫金色連線或拖尾；星點約 0.6 秒內淡出，最多保留 8 點，停止移動時不會持續新增，重玩時清除。
